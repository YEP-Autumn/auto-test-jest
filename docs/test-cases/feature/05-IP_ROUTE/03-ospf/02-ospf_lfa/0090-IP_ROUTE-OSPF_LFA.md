## 2. 组网与拓扑

```text
   逻辑端口 A -- DUTA PortB
   DUTA PortA   <=> DUTB PortA
   DUTB PortB   <=> DUTC PortB
   DUTC PortC   <=> DUTD PortC
   DUTD PortD   <=> DUTA PortD
   DUTC PortA   -- 逻辑端口 B
```

拓扑名称 / 来源：`four_devices_topo_links_type_6`（内置拓扑）。

| 链路                      | 网段            | 端点地址                                               | 开销  |
| ------------------------- | --------------- | ------------------------------------------------------ | ----- |
| 逻辑端口 A ↔ DUTA PortB | 198.51.100.0/24 | A 侧 198.51.100.1，测试仪 198.51.100.2                 | 1     |
| A-B                       | 10.0.12.0/24    | A=10.0.12.1，B=10.0.12.2                               | 1 / 1 |
| B-C                       | 10.0.23.0/24    | B=10.0.23.1，C=10.0.23.2                               | 1 / 1 |
| C-D                       | 10.0.34.0/24    | C=10.0.34.1，D=10.0.34.2                               | 1 / 1 |
| D-A                       | 10.0.41.0/24    | D=10.0.41.1，A=10.0.41.2                               | 1 / 1 |
| DUTC PortA ↔ 逻辑端口 B | 203.0.113.0/24  | C 侧 203.0.113.1，测试仪 203.0.113.2                   | 1     |
| Loopback0                 | 主机路由        | A=1.1.1.1/32，B=2.2.2.2/32，C=3.3.3.3/32，D=4.4.4.4/32 | 1     |

所有链路开销相同，A 到 203.0.113.0/24 形成两条等价路径：

```text
A-B-C
A-D-C
```

本用例验证 ECMP 的数据面分担，以及关闭 A-B 后 A-D-C 能接管，不出现整前缀黑洞。它不把“50ms 内 LFA 切换”作为严格判据，因为 A-D-C 本身就是 ECMP 主路径的一部分。

## 3. 预置条件

### 3.1 协议基线参数

| 参数         | 取值                             | 说明                                                   |
| ------------ | -------------------------------- | ------------------------------------------------------ |
| OSPF 进程    | 0（`router ospf`）               | 同一 VRF 仅支持一个进程                                |
| Area         | 0                                | 单区域                                                 |
| Network Type | point-to-point                   | 避免广播网络 DR/BDR 影响切换时间                       |
| Hello / Dead | 10s / 40s                        | 设备默认值                                             |
| LFA          | `fast-reroute per-prefix enable` | 在初始 OSPF 配置中使能                                 |
| BFD          | 不使能                           | 故障由本地接口 `shutdown` 触发；本用例聚焦 ECMP 转发面 |

### 3.2 初始状态

- 接口处于默认二层状态；OSPF 进程、Loopback、L3 地址、静态 ARP 和 LFA 配置为空。
- 拓扑后端已建立四设备环及两个测试仪接入链路。
- 现场保留：默认清理。

### 3.3 流量参数

| 参数     | 取值                                 | 说明                                 |
| -------- | ------------------------------------ | ------------------------------------ |
| 发送端口 | 逻辑端口 A                       | 接入 DUTA PortB                      |
| 接收端口 | 逻辑端口 B                       | 从 DUTC PortA 收包                   |
| 报文     | IPv4/UDP，198.51.100.2 → 203.0.113.2 | 目的地址属于 ECMP 前缀               |
| 流数量   | 5000 条不同 UDP 源端口               | 避免单条五元组只哈希到一条 ECMP 路径 |
| 包间隔   | 1ms                                  | 每个 burst 1 帧，burst 间隔 1ms      |
| 发送数量 | 5000 个                              | 发送时长约 6~8s                      |
| 丢包判据 | 接收匹配数 > 4950                    | 确认 ECMP 成员故障后没有整前缀黑洞   |

## 4. 测试步骤与预期结果

### 4.1 配置

DUTA/DUTB/DUTC/DUTD 按拓扑配置 OSPF 点对点接口、Loopback 和 `fast-reroute per-prefix enable`；DUTA 增加测试仪接入口 `198.51.100.1/24`，DUTC 增加测试仪出口 `203.0.113.1/24` 和静态 ARP `203.0.113.2 0002.0002.0002`。

### 4.2 基线检查与执行顺序

| 顺序 | 观测项 | 命令 | 预期 |
| --- | --- | --- | --- |
| 1 | 邻居状态 | `show ip ospf neighbor` | 四台设备邻居均为 `Full` |
| 2 | ECMP 下一跳 | `show ip route 203.0.113.2` | 同时出现 `10.0.12.2` 和 `10.0.41.1` |
| 3 | OSPF 路由 | `show ip ospf route` | `203.0.113.0/24` 同时有 `via 10.0.12.2` 和 `via 10.0.41.1` |
| 4 | LFA 状态 | `show ip ospf fast-reroute per-prefix` | `Fast-reroute per-prefix : enabled`，`Intra-area prefixes` 大于 0 |
| 5 | 连通性 | `ping 3.3.3.3` | `0% packet loss` |

基线检查通过后，按 4.3 执行流量发送与单路径故障注入，按 4.4 恢复 A-B 路径。

### 4.3 触发与流量发送

1. 在逻辑端口 B 启动抓包。
2. 逻辑端口 A 以 1ms 间隔发送 5000 个 IPv4 报文，UDP 源端口逐包递增。
3. 流量发送开始约 4s 后，关闭 DUTA 的 `<PortA>`，模拟 A-B 路径故障。
4. 等待路由只剩 `10.0.41.1`，并确认 `ping 3.3.3.3` 为 `0% packet loss`。
5. 停止发送和抓包，统计接收匹配数。

| 观测项 | 预期 |
| --- | --- |
| 发送报文数 | 5000 |
| 接收匹配报文数 | 大于 4950 |
| 切换后路由 | 只剩 `10.0.41.1`（A-D-C） |
| 切换后连通性 | `ping 3.3.3.3` 为 `0% packet loss` |

### 4.4 恢复

恢复 DUTA `<PortA>`，执行 `no shutdown`，等待 `10.0.12.2` 和 `10.0.41.1` 两条下一跳重新出现，确认 ECMP 恢复，并确认 `ping 3.3.3.3` 为 `0% packet loss`。

### 4.5 观测面

| 观测面 | 命令 / 方法 | 判定 |
| --- | --- | --- |
| 协议状态面 | `show ip ospf neighbor` | 四台设备邻居均为 `Full` |
| 表项面 | `show ip route 203.0.113.2`、`show ip ospf route` | 基线同时出现两条等价下一跳，故障后只剩 `10.0.41.1` |
| 计数 / 告警面 | `show ip ospf fast-reroute per-prefix` | `Fast-reroute per-prefix : enabled`，`Intra-area prefixes` 大于 0 |
| 转发面 | 逻辑端口 B 抓包匹配数、`ping 3.3.3.3` | 接收匹配数大于 4950，ping 丢包率 = 0% |
| 恢复 / 资源面 | 恢复后的路由与 ping 回显 | ECMP 重新形成，连通性恢复 |

### 4.6 判定标准

- 步骤 1：`show ip ospf neighbor` 中四台设备邻居均为 `Full`。
- 步骤 2：`show ip route 203.0.113.2` 同时出现 `10.0.12.2` 和 `10.0.41.1`；`show ip ospf route` 中 `203.0.113.0/24` 同时有 `via 10.0.12.2` 和 `via 10.0.41.1`。
- 步骤 3：`show ip ospf fast-reroute per-prefix` 显示 `Fast-reroute per-prefix : enabled`，且 `Intra-area prefixes` 大于 0；`ping 3.3.3.3` 丢包率 = 0%。
- 步骤 4：关闭 `<PortA>` 后，`show ip route 203.0.113.2` 只剩 `10.0.41.1, via`，`ping 3.3.3.3` 丢包率 = 0%。
- 步骤 5：逻辑端口 B 接收匹配报文数大于 4950，即 5000 个报文的丢包数小于 50。
- 步骤 6：恢复 `<PortA>` 后，`10.0.12.2` 和 `10.0.41.1` 两条下一跳重新出现，`ping 3.3.3.3` 丢包率 = 0%。
- Pass：步骤 1 至 6 全部满足，且第 5 章清理成功。
- Fail：步骤 1 至 6 任一必检项不满足，或清理失败。
- Blocked：邻居无法进入 `Full`、拓扑后端无法建立四设备环，或测试仪不支持 burst 发送与抓包计数。

## 5. 清理与恢复

四台设备删除 OSPF 进程、Loopback、接口地址、静态 ARP，并将测试仪接入接口恢复二层状态。
