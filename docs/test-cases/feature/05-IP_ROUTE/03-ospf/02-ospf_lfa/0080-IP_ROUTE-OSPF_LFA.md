## 2. 组网与拓扑

```text
   逻辑端口 A <=> DUTA PortD
   DUTA PortA   <=> DUTB PortA
   DUTA PortB   <=> DUTB PortB
   DUTB PortD   <=> 逻辑端口 B
```

拓扑名称 / 来源：`two_devices_topo_links_type_4`（内置拓扑）。

| 链路                      | 网段            | 端点地址                               | 开销    |
| ------------------------- | --------------- | -------------------------------------- | ------- |
| 逻辑端口 A ↔ DUTA PortD | 198.51.100.0/24 | A 侧 198.51.100.1，测试仪 198.51.100.2 | 1       |
| A-B 主链路                | 10.0.12.0/24    | A=10.0.12.1，B=10.0.12.2               | 1 / 1   |
| A-B 备链路                | 10.0.21.0/24    | A=10.0.21.1，B=10.0.21.2               | 10 / 10 |
| DUTB PortD ↔ 逻辑端口 B | 203.0.113.0/24  | B 侧 203.0.113.1，测试仪 203.0.113.2   | 1       |
| Loopback0                 | 主机路由        | A=1.1.1.1/32，B=2.2.2.2/32             | 1       |

A 到 203.0.113.0/24 的主路径经 PortA，LFA 备份下一跳为同一邻居 B 的 PortB。对 B 而言：

- `D(B,prefix)=1`；
- `D(B,A)=1`，`D(A,prefix)=2`；
- `1 < 3` 成立，B 通过备链路可作为 LFA。

## 3. 预置条件

### 3.1 协议基线参数

| 参数         | 取值                                        | 说明                             |
| ------------ | ------------------------------------------- | -------------------------------- |
| OSPF 进程    | 0（`router ospf`）                          | 同一 VRF 仅支持一个进程          |
| Area         | 0                                           | 单区域                           |
| Network Type | point-to-point                              | 避免广播网络 DR/BDR 影响切换时间 |
| LFA          | `fast-reroute per-prefix enable`            | 在初始 OSPF 配置中使能           |
| OSPF BFD     | `ip ospf bfd`                               | 两条 OSPF 点对点接口均使能       |
| BFD 检测     | `bfd interval mintx 3 minrx 3 multiplier 3` | 故障检测约 9ms                   |

### 3.2 初始状态

- 接口处于默认二层状态；OSPF、Loopback、L3 地址、BFD、静态 ARP 和 LFA 配置为空。
- 拓扑后端已建立两设备双链路及两个测试仪接入链路。
- 现场保留：默认清理。

### 3.3 流量参数

| 参数       | 取值                                 | 说明                        |
| ---------- | ------------------------------------ | --------------------------- |
| 发送端口   | 逻辑端口 A                       | 接入 DUTA PortD             |
| 接收端口   | 逻辑端口 B                       | 从 DUTB PortD 收包          |
| 报文       | IPv4/UDP，198.51.100.2 → 203.0.113.2 | 目的地址属于 LFA 受保护前缀 |
| 每周期数量 | 6000 个                              | 每个周期 1 包/ms            |
| 周期数     | 3                                    | 连续关闭/恢复 A-B 主链路    |
| 单周期判据 | 接收匹配数 > 5950                    | 单周期丢包少于 50           |

## 4. 测试步骤与预期结果

### 4.1 配置

DUTA/DUTB 配置两条 OSPF 点对点链路、Loopback、LFA，并在两条 OSPF 接口上使能 BFD。DUTB 增加测试仪出口 `203.0.113.1/24`、静态 ARP 和 `network 203.0.113.0/24 area 0`。

### 4.2 基线检查与执行顺序

| 顺序 | 观测项 | 命令 | 预期 |
| --- | --- | --- | --- |
| 1 | 邻居 | `show ip ospf neighbor` | 两条邻居均为 `Full` |
| 2 | BFD | `show bfd session detail` | 两条会话均为 `Session State : Up` |
| 3 | 主路径 | `show ip route 203.0.113.2` | 下一跳为 `10.0.12.2` |
| 4 | LFA 明细 | `show ip ospf fast-reroute per-prefix` | 目标前缀备份下一跳为 `10.0.21.2` |
| 5 | 直连连通性 | `ping 10.0.12.2`、`ping 10.0.21.2` | 均为 `0% packet loss` |

基线检查通过后，按下列顺序执行 3 个周期：

| 顺序 | 动作 | 说明 |
| --- | --- | --- |
| 1 | 周期 1 触发 | 按 4.3 执行流量发送与主链路故障注入 |
| 2 | 周期 1 恢复 | 按 4.4 恢复主链路并复核 LFA |
| 3 | 周期 2 触发与恢复 | 重复 4.3、4.4 |
| 4 | 周期 3 触发与恢复 | 重复 4.3、4.4 |
| 5 | 清理 | 按第 5 章执行 |

### 4.3 触发与流量发送

每个周期执行以下步骤，连续执行 3 个周期：

1. 在逻辑端口 B 启动抓包。
2. 逻辑端口 A 以 1ms 间隔发送 6000 个报文，发送不等待完成。
3. 流量发送开始约 4s 后，关闭 DUTA 的 `<PortA>`，模拟 A-B 主链路故障。
4. 等待路由切到 `10.0.21.2`，并确认 `ping 2.2.2.2` 为 `0% packet loss`。
5. 停止发送和抓包，统计 逻辑端口 B 的接收匹配数。

| 周期 | 故障接口 | 切换后路由 | 单周期判据 |
| --- | --- | --- | --- |
| 1 | DUTA `<PortA>` | 下一跳为 `10.0.21.2` | 接收匹配数 > 5950 |
| 2 | DUTA `<PortA>` | 下一跳为 `10.0.21.2` | 接收匹配数 > 5950 |
| 3 | DUTA `<PortA>` | 下一跳为 `10.0.21.2` | 接收匹配数 > 5950 |

每个周期的恢复动作见 4.4；恢复完成后再执行下一周期。

### 4.4 恢复

每个周期在 4.3 的流量统计完成后执行：

1. 在 DUTA `<PortA>` 执行 `no shutdown`，恢复 A-B 主链路。
2. 等待 `show ip route 203.0.113.2` 的下一跳回到 `10.0.12.2`。
3. 等待 `show ip ospf fast-reroute per-prefix` 中目标前缀的备份下一跳恢复为 `10.0.21.2`。
4. 确认 `ping 2.2.2.2` 为 `0% packet loss`。

3 个周期完成后，确认两台设备均无残留 `Down` 状态，主路径与 LFA 明细回到基线。

### 4.5 观测面

| 观测面 | 命令 / 方法 | 判定 |
| --- | --- | --- |
| 协议状态面 | `show ip ospf neighbor`、`show bfd session detail` | OSPF 邻居 `Full`，BFD 会话 `Session State : Up` |
| 表项面 | `show ip route 203.0.113.2`、`show ip ospf fast-reroute per-prefix` | 基线下一跳 `10.0.12.2` 且备份 `10.0.21.2`；故障后下一跳 `10.0.21.2`；恢复后下一跳 `10.0.12.2` 且备份 `10.0.21.2` |
| 转发面 | 逻辑端口 B 抓包匹配数 | 每周期接收匹配数大于 5950，丢包数小于 50 |
| 恢复 / 资源面 | 恢复后的路由与 LFA 明细 | 回到基线，无残留 `Down` 状态 |

### 4.6 判定标准

- 步骤 1：`show ip ospf neighbor` 中两条邻居均为 `Full`；`show bfd session detail` 中两条会话均为 `Session State : Up`。
- 步骤 2：`show ip route 203.0.113.2` 的下一跳为 `10.0.12.2`；`show ip ospf fast-reroute per-prefix` 中目标前缀的备份下一跳为 `10.0.21.2`；`ping 10.0.12.2`、`ping 10.0.21.2` 丢包率均为 0%。
- 步骤 3：每个周期关闭 `<PortA>` 后，`show ip route 203.0.113.2` 的下一跳为 `10.0.21.2`；`ping 2.2.2.2` 丢包率 = 0%。
- 步骤 4：每个周期的 逻辑端口 B 接收匹配数大于 5950，即单周期丢包数小于 50。
- 步骤 5：每个周期恢复 `<PortA>` 后，下一跳回到 `10.0.12.2`，目标前缀备份下一跳仍为 `10.0.21.2`，`ping 2.2.2.2` 丢包率 = 0%。
- 步骤 6：3 个周期均完成切换与恢复，两台设备均无残留 `Down` 状态。
- Pass：步骤 1 至 6 全部满足，且第 5 章清理成功。
- Fail：步骤 1 至 6 任一必检项不满足，或清理失败。
- Blocked：BFD 会话无法建立、拓扑后端无法建立双链路，或测试仪不支持 burst 发送与抓包计数。

## 5. 清理与恢复

DUTA/DUTB 删除 OSPF 进程、BFD 配置、Loopback、接口地址、静态 ARP，并将接口恢复二层状态。
