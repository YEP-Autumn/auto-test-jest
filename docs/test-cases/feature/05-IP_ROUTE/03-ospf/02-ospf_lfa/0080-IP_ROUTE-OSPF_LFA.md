# 并行链路连续 3 次故障恢复后，LFA 切换与单周期丢包不超过 50 个

> 本文依据 `docs/spec/test-case-template.md` 编写，覆盖本脚本的测试用例；文档中的子用例与脚本中的 `test()` 一一对应。

## 1. 基本信息

- 用例编号：`0080`

- 所属特性 / 分组：`05-IP_ROUTE` / `OSPF配置` / `OSPF LFA`
- 级别 / 类型：P1 / 性能
- 执行方式：自动化脚本 + 测试仪
- 预估耗时：约 5 分钟
- 关联：`test/feature/05-IP_ROUTE/03-ospf/02-ospf_lfa/`；设计模板见 [test-case-template.md](../../../../../spec/test-case-template.md)

## 2. 组网与拓扑

```text
   StreamPort.A <=> DUTA PortD
   DUTA PortA   <=> DUTB PortA
   DUTA PortB   <=> DUTB PortB
   DUTB PortD   <=> StreamPort.B
```

内置拓扑：`LinkConstraint.two_devices_topo_links_type_4`。

| 链路                      | 网段            | 端点地址                               | 开销    |
| ------------------------- | --------------- | -------------------------------------- | ------- |
| StreamPort.A ↔ DUTA PortD | 198.51.100.0/24 | A 侧 198.51.100.1，测试仪 198.51.100.2 | 1       |
| A-B 主链路                | 10.0.12.0/24    | A=10.0.12.1，B=10.0.12.2               | 1 / 1   |
| A-B 备链路                | 10.0.21.0/24    | A=10.0.21.1，B=10.0.21.2               | 10 / 10 |
| DUTB PortD ↔ StreamPort.B | 203.0.113.0/24  | B 侧 203.0.113.1，测试仪 203.0.113.2   | 1       |
| Loopback0                 | 主机路由        | A=1.1.1.1/32，B=2.2.2.2/32             | 1       |

A 到 203.0.113.0/24 的主路径经 PortA，LFA 备份下一跳为同一邻居 B 的 PortB。对 B 而言：

- `D(B,prefix)=1`；
- `D(B,A)=1`，`D(A,prefix)=2`；
- `1 < 3` 成立，B 通过备链路可作为 LFA。

## 3. 预置条件

### 3.1 协议基线参数

| 参数         | 取值                                        | 说明                             |
| ------------ | ------------------------------------------- | -------------------------------- |
| OSPF 进程    | 0（`router ospf`）                          | 同一 VRF 仅支持一个进程          |
| Area         | 0                                           | 单区域                           |
| Network Type | point-to-point                              | 避免广播网络 DR/BDR 影响切换时间 |
| LFA          | `fast-reroute per-prefix enable`            | 在初始 OSPF 配置中使能           |
| OSPF BFD     | `ip ospf bfd`                               | 两条 OSPF 点对点接口均使能       |
| BFD 检测     | `bfd interval mintx 3 minrx 3 multiplier 3` | 故障检测约 9ms                   |

### 3.2 流量参数

| 参数       | 取值                                 | 说明                        |
| ---------- | ------------------------------------ | --------------------------- |
| 发送端口   | `StreamPort.A`                       | 接入 DUTA PortD             |
| 接收端口   | `StreamPort.B`                       | 从 DUTB PortD 收包          |
| 报文       | IPv4/UDP，198.51.100.2 → 203.0.113.2 | 目的地址属于 LFA 受保护前缀 |
| 每周期数量 | 6000 个                              | 每个周期 1 包/ms            |
| 周期数     | 3                                    | 连续关闭/恢复 A-B 主链路    |
| 单周期判据 | 接收匹配数 > 5950                    | 单周期丢包少于 50           |

### 3.3 初始状态

- 接口处于默认二层状态；OSPF、Loopback、L3 地址、BFD、静态 ARP 和 LFA 配置为空。
- 拓扑后端已建立两设备双链路及两个测试仪接入链路。

## 4. 测试步骤与预期结果

### 4.1 配置

DUTA/DUTB 配置两条 OSPF 点对点链路、Loopback、LFA，并在两条 OSPF 接口上使能 BFD。DUTB 增加测试仪出口 `203.0.113.1/24`、静态 ARP 和 `network 203.0.113.0/24 area 0`。

### 4.2 基线观测

| 观测项   | 命令                                   | 预期                              |
| -------- | -------------------------------------- | --------------------------------- |
| 邻居     | `show ip ospf neighbor`                | 两条邻居均为 `Full`               |
| BFD      | `show bfd session detail`              | 两条会话均为 `Session State : Up` |
| 主路径   | `show ip route 203.0.113.2`            | 下一跳为 `10.0.12.2`              |
| LFA 明细 | `show ip ospf fast-reroute per-prefix` | 目标前缀备份下一跳为 `10.0.21.2`  |

### 4.3 三个切换周期

每个周期执行：

1. 在 `StreamPort.B` 启动抓包。
2. `StreamPort.A` 以 1ms 间隔发送 6000 个报文。
3. 发流约 4s 后关闭 DUTA 的 `<PortA>`。
4. 等待路由切到 `10.0.21.2`，并 `ping 2.2.2.2` 为 `0% packet loss`。
5. 停止发送和抓包，要求匹配数 > 5950。
6. 恢复 `<PortA>`，等待路由回到 `10.0.12.2`，并重新确认 LFA 目标前缀备份为 `10.0.21.2`。

### 4.4 预期结果

| 观测项       | 预期                               |
| ------------ | ---------------------------------- |
| 单周期匹配数 | 大于 5950                          |
| 单周期丢包   | 小于 50                            |
| 3 个周期     | 均能切换与恢复，无残留 Down 状态   |
| 恢复后 LFA   | 目标前缀备份下一跳仍为 `10.0.21.2` |

## 5. 清理与恢复

DUTA/DUTB 删除 OSPF 进程、BFD 配置、Loopback、接口地址、静态 ARP，并将接口恢复二层状态。
